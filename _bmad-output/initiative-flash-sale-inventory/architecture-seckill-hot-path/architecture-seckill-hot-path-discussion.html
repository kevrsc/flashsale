Seckill hot-path

Discussion diagram for a lead architect. The crowd is answered from one Redis script. The order is written afterward. The gateway and the sale application are Java 21 servlet processes on virtual threads. A box with a dashed border is outside this service, or it is a production placement this learning model does not run.

One qualification

  1. The gateway reads hash sale. It answers unidentified, closed, not open, or sold out in that order, and it does not run the script.
  2. Otherwise the sale application runs one Lua script. The script decrements the pool and stores the qualification document, or it does neither.
  3. The caller is told they qualified. That response does not wait for Kafka, Postgres, or the inventory service.
  4. Kafka carries that document. The order consumer inserts one row. A retry uses the same qualification id.
  5. A document still pending is published again until the order row exists. The consumer then asks the script to drop it.
  6. The report publisher sends one qualification report per order.

Close is the only publisher of the close report, and a second close repeats the same remaining count.
