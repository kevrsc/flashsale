- (event) Architecture run opened from the final PRD at prd-seckill-hot-path. The earlier spine at architecture-flash-sale-inventory stays as the record of the previous service.
- (constraint) The final PRD prd-seckill-hot-path and its addendum are binding. Settled product rules are inherited and not re-opened.
- (decision) Working mode is fast path. The spine is the build substrate. An additional HTML diagram is for a lead architect to discuss the shape. Inferred calls are tagged assumption.
- (decision) Paradigm is hot-counter qualification. Redis decides the pool in one Lua script. The sale application answers from that script. Kafka carries the qualification id. Postgres stores the order. Prevents a second path that deducts in Postgres on the click.
- (assumption) The broker is the Kafka already in this repo (apache/kafka 4.3.1, Spring Kafka 4.1.1). RabbitMQ also satisfies the PRD and was not chosen.
- (assumption) The edge in this learning model is a separate Spring Cloud Gateway process. A CDN sits in front in a production placement and is not a second filter implementation here.
- (decision) The Lua script records the qualification id in a Redis pending set in the same script as the decrement. A relay republishes pending ids to Kafka until the order row exists. The SQL outbox and Modulith are not used. Prevents a crash between decrement and publish from losing the id.
- (assumption) One sale application hosts the qualify API, the order consumer, and the report publisher. Many instances share Redis through one Kafka consumer group. The gateway is a second deployable.
- (assumption) Qualification reports and the close report are Kafka records for the inventory service. The attempt response does not call the inventory service.
- (version) Pinned from the repo and from Spring docs checked 2026-10-14: Java 17, Spring Boot 4.1.1, Spring Cloud 2025.1.3 (Oakwood, Boot 4.1.x from 2025.1.2; 2025.1.3 milestone says compatible with 4.1.x), Gateway 5.0.3, Circuit Breaker 5.0.3, Resilience4j 2.3.0, Spring Kafka 4.1.1, PostgreSQL 18.6, Kafka broker 4.3.1, Redis image redis:8.
- (decision) Circuit breaker is spring-cloud-starter-circuitbreaker-resilience4j on the sale application around the order insert, the report publish, and telemetry export. The Lua script is not wrapped. The gateway uses the reactive starter only for its own routes.
- (decision) User adopted all five fast-path choices. Kafka is the broker. Spring Cloud Gateway is the edge this learning model runs, and a CDN is not a second filter. The Redis pending set is the outbox. The order consumer stays in the sale application. Qualification reports and the close report are Kafka records. Prevents a later builder choosing RabbitMQ, a CDN-only edge, a SQL outbox, a third order-writer process, or a synchronous inventory call on the attempt.
- (version) Pinned from compose.yaml in this repo on 2026-10-14: OpenTelemetry collector 0.162.0, Prometheus 3.15.0, Grafana 13.2.3.
- (decision) The Lua script keeps no per-customer cap, cooldown, or prior-qualification set. The same userId may take another unit while a unit remains. Binds FR-3. Prevents a builder restoring the old limit of 3 or the one-hour wait.
- (decision) The attempt response returns from the Lua result and does not wait on telemetry export. An open breaker retries or sheds the order insert, the report, and the export, and does not stall the Lua script. Binds FR-10. Prevents a down collector holding the qualification response.
- (decision) Hash sale is the only sale record. Fields are itemId, allotment, remaining, open, closed, soldOut, and closeRemaining. The script is the only writer. Commands are load, start, attempt, close, and ack. Readers use HGET and do not EVAL. Answer order is unidentified, closed, not_open, sold_out, then decrement. Prevents the gateway answering not_open after close, and a remaining read that runs the attempt.
- (decision) The qualification document is JSON with qualificationId, saleId, userId, and itemId. saleId is the string sale. The id is a lowercase UUID built in the script with redis.sha1hex. Hash pending stores that document. sale.qualification carries the same bytes. orders is Flyway, primary key qualification_id, and the order consumer is the only inserter. ack runs only after the insert commits. Prevents a bare id and a stub order row.
- (decision) Only close publishes sale.close-report, and remaining is closeRemaining. Only the report publisher publishes sale.qualification-report, retried until the producer ack. An open breaker may shed telemetry export only. The gateway breaker does not wrap POST /attempts. Prevents two close counts and a shed report.
- (decision) POST /attempts body is userId and every answer is HTTP 200. Load, start, and close are POST /sales/load, POST /sales/start, and POST /sales/close. A refused load or start is HTTP 409. userId is unidentified when absent, empty, or whitespace only.
- (decision) sale and gateway are new Gradle subprojects. They do not depend on Modulith or the SQL outbox. The existing src tree is not extended. This learning model is compose.yaml plus redis:8.10.2. Local URLs stay the ones in application.properties, Redis on localhost:6379. Hosted provider, supervision, health, and alerting are deferred until the processes are no longer started by hand.
- (version) Gateway artifact is spring-cloud-starter-gateway-server-webflux 5.0.3. Sale breaker is spring-cloud-starter-circuitbreaker-resilience4j 5.0.3. Gateway breaker is spring-cloud-starter-circuitbreaker-reactor-resilience4j 5.0.3. Redis image is 8.10.2. kafka-clients stays 4.2.1 from the Boot 4.1.1 BOM. The Boot plugin wins over the Cloud BOM property that records Boot 4.0.8. Confirmed 2026-10-14 against Maven Central and the Spring Cloud 2025.1.3 announcement.
